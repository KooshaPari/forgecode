# Search audit research

- Scope: pending conversation search changes only. Preserve unrelated pending mutation/UI edits. No commits or pushes. Keep focused changes in the preexisting large repository file.
- `forge_domain/src/repo.rs` specifies raw FTS5 MATCH expressions, including multiword AND and prefixes. The simplified whitespace/substrings parser cannot satisfy that contract for phrases, operators, token boundaries, stemming, or column filters.
- Active schema: `2026-08-27-180000_fts5_unicode61_highlight/up.sql` defines `title, content, cwd`, `tokenize='unicode61 remove_diacritics 1'`. Use an isolated one-document in-memory FTS5 evaluator with that same schema for streamed legacy candidates. This does not write to attached history or build an unbounded legacy index. Match semantics are equivalent, ranking remains primary local BM25 plus legacy recency, not global BM25. Initial research stopped at the earlier porter migration. The equivalence regression exposed the newer tokenizer: `run` must NOT match `running`. Implementation and explicit expected behavior now follow the active unicode61 migration.
- SQLite reference: https://sqlite.org/fts5.html (MATCH grammar, prefix queries, phrase queries, column filters, porter tokenizer). No new dependencies required: Diesel/SQLite already provides FTS5.
- LIKE recovery is deliberately literal, not FTS syntax. Apply the entire escaped query to plaintext and compressed rows, independently for local and legacy sources. Match ASCII case folding consistently with SQLite's default LIKE behavior. Blank queries return no results.
- `conversations_all` already applies local-wins shadowing and workspace/unscoped-legacy visibility. Reuse it.
- Collect each source in recency order with deduplication before its hit quota. Read each row once rather than combining plaintext/compressed hit lists. For LIKE, combine and sort first, then take the globally newest hits. Only replace the oldest selected local with the newest legacy if truncation would otherwise starve legacy. This does not reserve a local quota when legacy rows are newer. Preserve local BM25 order and the intentional legacy slot for successful FTS.
- Limits bound retained unique hits per source, not candidates scanned, decompression size, or SQLite sorting work. A rare/no match may require scanning all eligible candidates. No arbitrary candidate cap is safe. SQLite may materialize an ORDER BY internally. One legacy document at a time is indexed, and the evaluator is dropped after the search.
- Existing targeted tests cover visibility, shadowing, compressed content, and legacy reservation. New tests will cover source starvation, duplicate underfill, literal multiword semantics, empty/syntax-only input, recency, and actual FTS syntax equivalence.
